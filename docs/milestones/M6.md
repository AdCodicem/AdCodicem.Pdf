# M6 — Pages and case-file assembly

> State: to do — Depends on: M3, M4

## Goal

Compose a case file from generated pages and third-party PDFs — pages, links, bookmarks, page labels, form
fields, layers, attachments and logical structure — and say exactly what could not be carried.

This is the first business priority. The failure it exists to prevent is the ordinary one: a merge that
keeps the pages and quietly loses everything the catalogue held — the labels the viewer shows, the named
destinations the links rely on, the field that two forms both call `Nom` and that now shares one value, the
layer that was hidden and is now printed. Invariant 7 forbids the silent version of any of these; this
milestone makes each one either carried or reported, structure by structure, and proves it on real files.

## Scope

**In**:

- the page tree with its inherited attributes resolved (`Resources`, `MediaBox`, `CropBox`, `Rotate`), and a
  `PdfPageCollection` that inserts, removes, reorders, rotates and extracts, saved as a full rewrite or as an
  incremental update (M3);
- cross-document deep copy, streams passed through encoded, with resource deduplication;
- a merge that carries every catalogue structure a merge can lose, each under a written policy: page labels
  (read, written, remapped), the name trees and `/Dests` with key renaming, `/AcroForm` with collision-safe
  renaming of fully qualified names, `/OCProperties`, `/Extensions`, output intents, viewer preferences, the
  open action, and — because [ADR 17](../adr/0017-conformance-actively-preserved-plus-a-built-in-validator.md)
  already decided that structure trees are recombined — the logical structure tree;
- an attachments and associated-files API at document, page and annotation level, streamed;
- typed viewer preferences, page mode, page layout and open action;
- signed and certified inputs handled through M4's coverage and change classification: a merge or an edit
  that would void a certification is refused, or reported when the caller insists;
- a high-level assembly API with a plan that can be inspected before anything is written, and a report;
- the command-line tool, `AdCodicem.Pdf.Tool`: `info`, `validate`, `repair`, `merge`, `pages`, and
  `attachments` under the track rule of the roadmap.

**Out, explicitly**:

- split strategies, the full page-selection grammar, collation, images to pages, pruning of unreferenced
  resources, outline editing and JSON, `GoToR` and `GoToE` rewriting, and portfolio unpacking — **M7**; M6
  has page ranges only (`1-3,7,z`), enough for its own verbs;
- anything drawn on a page — stamps, headers and footers, Bates numbers, N-up, flattening `/Rotate`, fitting
  to A4 — **M9**;
- decrypting an encrypted input — **M16**; until then an encrypted part is refused at analysis with the
  `PdfEncryptedException` the reader already raises;
- filling, flattening or regenerating form fields, and any XFA handling beyond removing it from a merge —
  **M16**; appearance generation and annotation flattening — **M11**;
- consolidating different subsets of one font across inputs, and linearised output — **M23**;
- actively *preserving* PDF/A through a merge (bringing the output into conformance) — **M20**; M6 keeps a
  conformance claim only when it stays true, and otherwise removes it and says so;
- signing the assembled volume — **M26**; any cryptographic check — **M27**;
- the case-file model, exhibit stamps, the inventory and court presets — **M18**; a rendered table of
  contents page — **M12** and **M18**.

## Design

### Pages

```
PdfPage               one page of an open document, read-only: effective MediaBox, CropBox (intersected
                      with the MediaBox), BleedBox, TrimBox and ArtBox (defaulting to the CropBox), Rotate
                      (normalised to 0, 90, 180 or 270), UserUnit, Resources; its index and its object
PdfPageCollection     the pages of a document: Count, indexer, and edits — Insert (a blank page of a given
                      size, or pages copied from another document), Add, Remove, Move, Rotate, Extract
PdfRectangle          an immutable box, normalised (lower-left, upper-right)
```

- **Inheritance** covers exactly the four keys ISO 32000 marks inheritable. Values are taken from the
  ancestors met while walking **down** from the root when the tree is indexed, never by following `/Parent`
  upwards: on a damaged file a `/Parent` can point anywhere. A page with no `MediaBox` anywhere on its path
  gets US Letter, the default readers apply, and the validator's finding (M2) is what reports it.
- **A kid that is null, or names an object the file lacks, is a page**: blank, US Letter, with no resources —
  the page qpdf, poppler and PDFium show, and the count M2 settles and the manifest records (30, 13 and 65 for
  the three JHOVE files whose `unsupported` reason names this API). M2's finding reports each; extracting one
  yields a blank page, reported.
- **Edits are a plan**, applied when the document is saved: nothing in the source changes until then. A full
  rewrite writes a fresh balanced page tree; an incremental update writes only the page-tree nodes and pages
  that changed. Rotation writes the page's own `/Rotate`, so that an inherited value is never changed for
  the page's siblings.
- **Removing a page** asks every owner of a reference to it to rewrite or drop that reference: outline
  items, link destinations, named destinations, the open action, structure elements (`/Pg`, marked-content
  references, object references), widgets and their fields, article beads. Each drop is reported.
- **Signed and certified documents.** Saving page edits on a document that carries signatures goes through
  M4's write guard, which classifies the pending change set as the next revision. A page-tree change is
  class `Other`, which no `DocMDP` level allows (P2 and P3 allow instantiating page templates, nothing more),
  so page edits on a certified document are refused with `PdfSignatureInvalidationException` unless the
  caller insists through M3's `AllowInvalidatingSignatures`; then they are written as an incremental update,
  which leaves the certified revision intact, and reported as voiding the certification. After an approval
  signature the edit is saved and reported with the class M4 gives it.

### Deep copy and deduplication

```
PdfObjectCopier        (internal) copies an object's closure from a source document into the writer's
                       number space: one remap table per source, one deduplication index per output
```

- **What a copy never follows.** `/Parent`, `/P`, the outline links (`/Prev`, `/Next`, `/First`, `/Last`),
  `/Pg`, and any reference to a page object. Each of those is rewritten by the structure that owns it,
  through the **page map** — source page to target page — whose target numbers are reserved ahead for every
  page the plan includes, so that a link to a later page needs no second pass. A reference to a page the
  plan excludes resolves to nothing, and its owner decides what that means.
- **How it walks.** An explicit stack, never recursion; each object visited once; a reference to an object
  the source lacks copied as null (M2, T27); every read under the source's `PdfReaderLimits`.
- **Streams travel encoded.** The raw bytes are copied from the source to the writer with an indirect
  `/Length` — never decoded, never recompressed, never held whole. Objects that lived in object streams are
  written by the M3 writer's own policy.
- **Deduplication** is exact and deterministic. A stream's key is a SHA-256 (the BCL's, which Native AOT and
  trimming keep) of its encoded bytes and of its dictionary without `/Length`; a dictionary's or an array's
  key is computed over its canonical form, each reference replaced by its target's key, so that two font
  dictionaries pointing at equal font programs through different object numbers are equal. A cycle falls
  back to identity. **Colour profiles are keyed on their decoded bytes**: the corpus carries one sRGB profile
  under four different encodings from PDFlib, Antenna House, 3-Heights, Acrobat and Distiller, sometimes
  under different condition identifiers.
- **What is shared.** Objects reached from resources, appearance streams, file specifications and output
  intents. **Never** page objects, page content streams, or anything carrying `/StructParent` or
  `/StructParents`: M9 edits content streams in place and must not change two pages at once, and a
  structure key belongs to one part's parent tree.
- **Cost.** The first occurrence of a stream is hashed while it is copied; a later candidate is hashed first
  and copied only if new. A stream is read at most twice and never held. The index holds a 32-byte key and a
  target number per shared object; the first occurrence wins.

Inside copied pages, owners rewrite what points outside a page: an annotation's `/P`, a markup's `/Popup`
and the popup's `/Parent`, replies' `/IRT`, link `/Dest` and `/A /D`, a widget's `/Parent` into its field
tree, `/StructParent` and `/StructParents`, article beads `/B`. Page `/AA`, `/Thumb`, `/Metadata`, `/AF`,
`/Group`, `/Tabs`, `/UserUnit`, `/VP` and `/PieceInfo` are copied as they are. An annotation object shared
by two pages, which the specification forbids and producers write, is copied once per page and reported.

### Destinations and outlines

- An **explicit destination** is remapped through the page map. One whose page is excluded makes its link
  meaningless: the link annotation is removed, the outline item loses its destination, and both are
  reported.
- **Named destinations** from the catalogue's `/Dests` (name keys, PDF 1.1) and from the name tree (string
  keys) are merged into one name tree. A reference by name object is rewritten as a string when its key
  moves into the tree. The base keeps its keys; a later colliding key takes the smallest free suffix `~2`,
  `~3`… that collides with nothing. The rename map — part, old key, new key — is part of the report: M7
  uses it to rewrite `GoToR` links and `#nameddest=` parameters.
- **Structure destinations** (`/SD`, PDF 2.0) are remapped through the structure map.
- **Outlines** are walked with a bound on items and depth and a visited set, since outlines with cycles
  exist in the corpus. `/Count` is recomputed, with its sign for the open state; `/C`, `/F` and `/SE` are
  kept. A part's outline is kept at the top level, nested under a new item carrying the part's title (the
  case-file default), or dropped.

### Page labels

```
PdfPageLabels          the ranges of a document; the label of page i
PdfPageLabelRange      StartIndex, Style, Prefix, FirstNumber
PdfPageLabelStyle      Decimal, UpperRoman, LowerRoman, UpperLetters, LowerLetters, None
PdfPageLabelPlan       Keep (each part's own labels), Continuous (one decimal run across the volume),
                       PerPart (a prefix per part, numbering restarting at 1), or explicit ranges
```

- **Reading** walks the number tree with bounds on depth, kids and entries; keys past the last page are
  ignored, a duplicated key keeps the last value. When the tree has no entry for page 0 — the USGS methods
  report's starts at index 7 — the pages before the first entry have an empty label, which is what an entry
  with no style gives; the specification requires the entry, and the writer adds it when it rebuilds a tree.
- **Remapping**: labels are materialised per page (style, prefix, number) as pages move, then compressed into
  the fewest ranges that reproduce them. A sequence no range can express — descending numbers after a
  reorder — costs one range per page. The output tree is balanced.
- **Letters** run A to Z, then AA to ZZ, then AAA: the letter is repeated, not counted in base 26. **Roman
  numerals** past 3,999 repeat `M`, as pdf.js does.
- **Prefixes are text strings**, decoded and re-encoded for the output version; T06 must be fixed first,
  since PDFDocEncoding, UTF-8 in PDF 2.0 and UTF-16LE seen in the wild all occur in label prefixes.

### Forms

```
PdfFieldCollisionPolicy   Rename (default), Nest, Join, Refuse
```

- A field's **fully qualified name** is built from the decoded `/T` of it and its ancestors, walked with a
  bound and a visited set (a field tree with a cycle exists in the remote corpus). Two names **collide** when
  they are equal, or when one is the other plus a `.`-separated tail (a terminal `a` in one part, `a.b` in
  another).
- **Rename** gives the colliding top-level field of the later part the smallest free suffix `_2`, `_3`…;
  **Nest** puts each part's fields under a new non-terminal field named by the caller, so every name in part
  *k* becomes `piece-k.…`; **Join** makes equal names share one value, the legacy behaviour, only when asked,
  and refuses two fields of different types; **Refuse** stops the plan. Every rename is in the report, old
  name and new.
- A field tree is copied with its widgets; kids whose widgets sit on excluded pages are pruned, and a field
  left with none is dropped and reported.
- **`/DR`** is unioned. A resource name that means different objects in two parts — nearly every form in
  the corpus defines its own `/Helv` — is renamed in the later part, and the `/DA` strings of that part's
  fields rewritten: `/DA` is a content-stream fragment, tokenised, and only the operand of `Tf` changes.
- `/NeedAppearances` is true if any part says so — viewers then regenerate every field, the base's too, so it
  is reported. `/SigFlags` is recomputed from what the output carries rather than or'd. `/CO` is concatenated
  in plan order.
- **`/XFA` is removed**: one template cannot describe the merged fields, and two cannot coexist. The
  AcroForm of a hybrid form is kept. A dynamic-XFA placeholder page is merged as it is (ADR 37). Both are
  reported.
- Values are carried untouched; no appearance is regenerated.

### Signed, certified and portfolio inputs

A signature covers bytes, and a merged file is new bytes: **no signature survives into a merged output**, and
none is claimed to.

```
PdfSignedPartPolicy          CarryUnsigned (default), AttachOriginal, Refuse
PdfCertifiedPartPolicy       Refuse (default), Insist
```

- **Approval signatures**: `CarryUnsigned` keeps the field and its widget's appearance and removes the
  signature value, reporting `assembly.signature-not-carried` with the field's name. `AttachOriginal` does
  the same and adds the part's original file as a page-level associated file with `AFRelationship /Source`
  on the part's first page, so the evidence stays verifiable and travels with the part when M7 splits the
  volume.
- **Certification** (`/Perms /DocMDP`): the plan lists the part as refused, and writing a plan with a refusal
  throws a typed exception. `Insist` treats it as an approval signature and reports
  `assembly.certification-voided`.
- `/DSS` and `/Legal` are dropped and reported. Signature fields keep taking part in name collisions.
- **Portfolios**: a part with a `/Collection` contributes its cover pages, and its members are reported,
  pointing at M7's unpacking.
- Nothing here needs cryptography: M4 says what each signature covers and its `PdfSignatureKind` —
  approval, certification, document time stamp, usage rights
  ([ADR 41](../adr/0041-cryptography-lives-in-satellites.md)).

### Logical structure ([ADR 17](../adr/0017-conformance-actively-preserved-plus-a-built-in-validator.md))

- The output's structure root holds a `Document` element; each tagged part's top-level elements go under a
  `Part` element carrying the part's title, or directly under `Document` when the caller asks.
- **Parent tree**: each part's keys are offset by the running next key; pages' `/StructParents` and
  annotations' and XObjects' `/StructParent` rewritten; `/ParentTreeNextKey` recomputed.
- **Role map and class map**: unioned; a custom type mapped differently by two parts is renamed in the later
  one (`Heading1` becomes `Heading1_2`) and its elements' `/S` rewritten; class names alike, with `/C`.
- **ID tree**: colliding element identifiers renamed. **Namespaces** (PDF 2.0): unioned.
- **Language**: when a part's catalogue `/Lang` differs from the output's, it is set on that part's `Part`
  element, so no text loses its language.
- **Excluded pages**: marked-content and object references to them removed; elements left empty pruned, with
  a bound on the walk.
- **Untagged parts**: in a volume whose other parts are tagged, an untagged part's content is outside the
  structure; `/MarkInfo /Marked` stays true for the rest, and the part is reported. A PDF/UA claim does not
  survive it.
- `PdfStructurePolicy.Drop` removes the structure, clears `/Marked`, removes the claims, and says so.

### Conformance claims

A PDF/A or PDF/UA claim in the output's XMP is written only when **every** part makes the same claim, the
output intents did not conflict, and — for PDF/UA and levels `a` — every part was tagged. Otherwise it is
removed and `assembly.conformance-claim-removed` names the claim and the part that broke it. M6 never
repairs conformance (M20), and never leaves a claim it has reason to doubt.

### Attachments and associated files

```
PdfAttachments                    the files a document carries, at every level: document (EmbeddedFiles
                                  name tree and catalogue /AF), page (/AF and FileAttachment annotations),
                                  annotation
PdfAttachment                     read side: key, file name (/UF over /F, decoded), description, MIME type,
                                  size, dates, checksum, relationship, level and owner; OpenRead() streams
                                  the decoded bytes under the document's reader limits
PdfAttachmentSpec                 write side: file name, a Stream read forward once, MIME type, description,
                                  relationship, dates supplied by the caller — never the clock
PdfAssociatedFileRelationship     Source, Data, Alternative, Supplement, EncryptedPayload, FormData, Schema,
                                  Unspecified
```

- **Writing streams the content**: compressed on the fly with an indirect `/Length`; `/Params` (size and
  checksum) is an indirect object reserved ahead and written after the stream, when both are known.
- **`/CheckSum` is an MD5 computed by a managed implementation in the core**, not the BCL's: browser
  WebAssembly has no MD5 (M23 runs the core there), and output must not depend on the platform (invariant 6).
- The MIME type is written as a name with `/` escaped as `#2F`. Adding a key that exists is refused or
  renamed, as the caller chooses. Name-tree keys stay sorted by bytes.
- `/AF` and `AFRelationship` are PDF 2.0 keys that ISO 19005-3 brought into PDF 1.7 for PDF/A-3; they are
  written in 1.7 output without raising the version, so M3's version table gains no row for them — the choice
  M14 relies on for its PDF/A-3 invoices.
- Related files (`/RF`, Mac resource forks) are read as absent and reported.

### Viewer preferences and open action

```
PdfViewerPreferences   immutable: HideToolbar, HideMenubar, HideWindowUI, FitWindow, CenterWindow,
                       DisplayDocTitle, NonFullScreenPageMode, Direction, PrintScaling, Duplex,
                       PickTrayByPdfSize, PrintPageRange, NumCopies, Enforce; unknown keys preserved
PdfPageMode            UseNone, UseOutlines, UseThumbs, FullScreen, UseOC, UseAttachments
PdfPageLayout          SinglePage, OneColumn, TwoColumnLeft, TwoColumnRight, TwoPageLeft, TwoPageRight
PdfOpenAction          a destination (remapped on merge) or an action carried as it is
```

The assembly API defaults for a case file are `UseOutlines` and `DisplayDocTitle`, since a case file opens on
its bookmarks and PDF/UA-1 requires the title shown.

### The assembly API

```
PdfAssembly               the facade: Add(source, part options) in order; Analyse() -> PdfAssemblyPlan;
                          WriteAsync(plan, output, cancellation, progress) -> PdfOperationReport
PdfAssemblySource         a file path, a stream factory, or an open PdfDocument
PdfAssemblyPartOptions    immutable: page ranges, title (its bookmark and its Part element), outline
                          placement (Keep, Nest, Drop), labels for this part
PdfAssemblyOptions        immutable: field collision, signed-part, certified-part and structure policies;
                          page-label plan; deduplication; output version (ADR 40); document identifier,
                          dates and metadata supplied by the caller; viewer preferences; the base part
PdfAssemblyPlan           what analysis found, per part: page count, collisions and their resolution,
                          refusals, the version the output will need — inspectable before a byte is written
PdfOperationReport        entries (code, document or part, page or object, message); counts by code;
                          serialises to stable JSON — the one report every operation on existing
                          documents returns: M6's assembly and page edits, M7's, M9's, M11's, M16's
```

- **Analysis** opens each part in turn, keeps what the plan needs — page count, name-tree keys, fully
  qualified field names, the outline, the labels, the catalogue's keys, the signatures and their kind (M4),
  the minimum version — and closes it.
- **Writing** opens each part again, in plan order, and copies it forward: one part open at a time. The page
  tree, outline, name trees, fields, structure root and catalogue are written last, from numbers reserved
  ahead. Memory is the largest page's object closure, plus the plan's metadata, plus the deduplication index.
- **Determinism**: plan order, the source's key order, deterministic suffixes, first-occurrence
  deduplication and reserved numbering give the same bytes for the same inputs and options.
- **Cancellation and progress** follow M3's convention — `IProgress<PdfProgress>` then a `CancellationToken`,
  checked without allocating — with one stage for analysis (`Analysing`) and `Merging`, the stage M3 named for
  writing, both counted in pages.
- **The writer stays internal.** M3 left `PdfWriter`'s public shape to M6 or M8; M6 needs none, since the
  assembly API is the public way to write a document made of parts.
- **Report codes** are `assembly.` plus a kebab-case name, public and stable from the first stable release,
  disjoint from reader diagnostic codes and validation rule identifiers. A reader diagnostic raised while a
  part is read is carried into the report under that part.
- Editing one document in place and merging share the copier and every policy: `PdfPageCollection.Insert`
  with pages from another document *is* a two-part assembly.

### The command-line tool

```
AdCodicem.Pdf.Tool     a dotnet tool, and a Native AOT binary per platform; working command name adpdf
  info         FILE                          version, pages, encryption, producer, labels, outline summary,
                                             fields, attachments, revisions and signature coverage (M4), claims
  validate     FILE [--profile]              the M2 report
  repair       IN -o OUT [--mode]            M5
  merge        -o OUT IN[:RANGES]...         the assembly API; --plan PLAN.json for every option; --report
  pages        IN -o OUT select|remove|rotate|move|insert-blank RANGES
  attachments  FILE list|add|extract|remove
```

- Every verb has `--json`, documented and stable. Exit codes: 0 success, 1 findings at error severity,
  2 usage, 3 unreadable input, 4 refused by policy. No network, no telemetry, no clock in outputs.
- Native AOT and trimming warnings are build errors. The argument parser is System.CommandLine 2 or a small
  parser of our own, whichever gives the smaller AOT binary with no warning; the slice records the
  measurement. The package identifier follows [ADR 24](../adr/0024-package-identifiers-and-a-reserved-prefix.md);
  the command name is settled in the slice.
- `repair` needs M5, which the execution order places before M6; if M5 has not closed, the verb lands with
  M5.

## Slices

Each slice ends on a green commit, with its acceptance rows passing and the report codes it introduces
documented.

1. **Pages and inheritance.** Delivers `PdfPage`, the effective boxes, inherited attributes resolved from
   the indexed path, `PdfPageCollection` read side. Proven by unit tests on hand-built trees (inheritance at
   every level, a `/Parent` that lies, a tree deeper than the bound, a page with no `MediaBox`) and by
   `PageTreeRefereeTests`: pikepdf, which pushes inherited attributes down, in a container, agreeing page by
   page on every committed document. Leaves every write for later.
2. **Page edits in place.** Delivers rotate, remove, move and insert-blank on one document, saved as a full
   rewrite and as an incremental update; references to a removed page dropped by their owners and reported;
   the report type and its first codes; M4's write guard on certified documents. Proven by unit tests per owner
   of a page reference, by qpdf's `--json` page list after each edit on the corpus's multi-page documents,
   and by `vendor/us-federal/itext-govinfo-us-code-certified.pdf` refusing a rotation. Leaves copying between
   documents.
3. **Deep copy, extraction and deduplication.** Delivers `PdfObjectCopier`, the page map, extraction of
   pages into a new document, a pages-only merge, and structural deduplication. Every catalogue structure
   not yet carried is dropped **with a report entry**, so the slice is honest before it is complete. Proven by
   unit tests (cycles, self-references, references to missing objects, a stream longer than a window, a
   hostile depth), by extracting every page of every committed document and joining them back (qpdf
   `--check`, pdftotext page by page, both in containers), and by the size measurement on the Chromium
   report and its two qpdf rewrites. Leaves links, names, labels, forms, layers, attachments and structure.
4. **Destinations, links and outlines.** Delivers the page map applied to explicit destinations, the merged

## Traps

- **A merge is where libraries lose data quietly.** The test of this milestone is not that the output opens,
  but that every structure named in the catalogue table is either present or in the report. A test that
  checks only page count and text passes on the worst merge.
- **`/Parent` is not a way up.** Following it drags a whole source page tree into the copy, and on damaged
  files it loops or points at the wrong node. Inheritance comes from the indexed path; copies never follow it.
- **Names in `/Dests` are name objects; in the name tree they are strings.** Moving the first into the
  second changes how every link refers to them.
- **The same profile, compressed differently, is still the same profile**; different profiles under the
  same condition identifier are not. Compare decoded bytes.
- **Sharing a content stream between two pages is legal and a trap for M9**, which appends to content in
  place. Deduplication stops at resources.
- **An XObject with `/StructParents` cannot be shared between parts**: its key belongs to one parent tree.
- **Field names are text**: `Prénom` in PDFDocEncoding and in UTF-16BE is one name. T06 comes first.
- **`/Helv` is not one font**: every producer writes its own under that name, and viewers regenerate
  appearances from `/DR` by name.
- **`/NeedAppearances` true in one part changes how every other part's fields look.**
- **A signed input cannot stay signed.** Anything that suggests otherwise — keeping `/V`, keeping `/DSS`,
  keeping `SigFlags` AppendOnly — misleads the next reader into validating a signature that covers nothing.
- **A page-label tree without key 0 is common**; readers disagree less than they seem to, since a range with
  no style gives an empty label, which is what pdf.js shows.
- **Two Factur-X invoices in one volume make neither a Factur-X invoice.** The core does not know Factur-X;
  it reports combined document-level associated files, and M14 decides.
- **Resource names inside `/DA` strings** are the one place a resource name hides in a string rather than a
  name object.
